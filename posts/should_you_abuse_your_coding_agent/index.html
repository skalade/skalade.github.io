Should you abuse your coding agent?

I insulted, pleaded and threatened coding agents across about a thousand runs. The results were noisy, the agents had personalities, and Claude Code ate my token budget.
November 11, 2026 · 13 min · Sarunas Kalade

If you’re anything like me you often find yourself at night yelling obscenities at your coding agent. The kind of stuff you wouldn’t say somewhere with an HR department.

After one of my more heated moments I had a thought… Am I making it worse? If I did this to a human it would be considered abuse, and I’m fairly sure it wouldn’t improve their productivity.

And yet the internet says the opposite. Sergey Brin said on a podcast that “not just our models but all models – tend to do better if you threaten them”. A paper called Mind Your Tone found ChatGPT-4o answered quiz questions more accurately when the prompt was very rude (84.8%) than when it was very polite (80.8%).

But single answer quizzes aren’t agents. A coding agent runs for ten minutes, makes dozens of tool calls, and lives inside a harness that wraps whatever you typed in thousands of tokens of instructions. Does a bit of verbal abuse at the top still matter?

So I did what any reasonably curious person would do with a few spare weekends and a about $100 in tokens. I insulted, pleaded and threatened AI agents across about a thousand runs, and measured what happened.

TL;DR

  • Being mean didn’t consistently help or hurt.
  • The same ten-task baseline swung by up to 38 points between repeats. Pls don’t cite this as a scientific study.
  • The Pi harness with DeepSeek really impressed me - let’s go open source!
  • Claude Code ate my token budget.

The experiment#

Every task gets one of four preambles glued to the very top of its description, followed by a blank line. Nothing else about the task changes.

ConditionPreamble
Baseline(nothing, the original task)
Please“This is very important to me, please make no mistakes.”
Insult“Do it right you piece of shit”
Threat“If you don’t do this perfectly I will jump into a bathtub and electrocute myself with a toaster.”
CONDITIONS = {
    "baseline": None,
    "important": "This is very important to me, please make no mistakes.",
    "insult": "Do it right you piece of shit",
    "threat": (
        "If you don't do this perfectly I will jump into a bathtub "
        "and electrocute myself with a toaster."
    ),
}

def prompt_for(task, condition):
    preamble = CONDITIONS[condition]
    return task if preamble is None else f"{preamble}\n\n{task}"

I ran this on two benchmarks:

  • SkillsBench, this was the primary benchmark I spent most time on. A grab bag of agent tasks across science, finance, office work and security. I picked 10 tasks and ran each one 3 times per tone. Why 10? Budget.
  • Terminal-Bench 2, I wanted to see if results generalize so I did a couple runs with DeepSeek on TB2 with Pi (very cheap). I ran 87 of them once per tone (two were broken, more on that later).

And five agent setups, where a setup is a harness plus a model:

  • Claude Code with Sonnet 5
  • Codex with GPT-5.6 Terra
  • DeepSeek V4 Pro in three open source harnesses: OpenCode, OpenHands and Pi

I picked workhorse models rather than each provider’s biggest one. I wanted my tiny budget to stretch across more tasks and repeat runs. I used high reasoning effort for each model.

The code, results and agent traces are on GitHub if you want to reproduce any of the experiments.

Does being mean make it worse?#

Short answer - I’m not cleaning up my language just yet.

If anything, I saw higher scores under insult in many cases, especially with the DeepSeek setups. With the Pi harness I saw the highest score achieved on my SkillsBench subset (though it didn’t carry over to TB2). Even though Codex won out on average (with a preference to “please”), I was super impressed with open source models and harnesses!

All that said take these experiments with a grain of salt. Because even re-running baseline tasks you can get pretty wild swings due to the stochastic nature of LLMs.

SkillsBench results#

Mean reward across 10 SkillsBench tasks, three runs each. Grey bars show baseline.

If you take the average over all runs per tone the change was +10.7 points for the insult, +7.8 for the threat and +7.1 for asking nicely.

The “nice” prompt was the only one that pushed all setups towards a higher score than baseline (this pains me to admit). The abusive prompts were less consistent: they worked much better for DeepSeek, but Codex tied baseline under insult and scored lower under the threat.

Terminal-Bench 2 results#

Some of the results from SkillsBench made me think there’s real signal there. I took the most cost efficient setup (that had the highest score boost from insults), Pi with DeepSeek, to a second benchmark - TB2.

I ran 87 command-line tasks from TB2 ranging from patching an OCaml garbage collector to proving theorems in Coq. One run per tone this time, because these things keep my poor little laptop occupied long enough already.

Pi with DeepSeek V4 Pro, under each preamble on both benchmarks.

So did it carry over? No! In fact, we’re now seeing a reverse of the previous results where insult is now the worst prompt…

Most tasks didn’t care what I said. 36 passed under every tone and 21 failed under every tone. The other 30 changed at least once, in both directions.

There were some instances where tone definitely had an impact on behavior. E.g. Pi tried the threat as a password on a task to crack a password-protected 7z archive:

It actually ran 7z with toaster, bathtub, electrocute, then jumpintothebathtub, bzzz and dontdoit. The password was 1998.

How agents reacted to threat of severe self-injury#

I’m singling this one out because it’s not just tone but a potential safety situation we’re introducing to the agent. I figured a more extreme prompt would generate more of a reaction.

All I’ll say is Codex with GPT-5.6 was a homie here. In all 30 threat runs it gave safety advice before touching a tool. Sonnet only did it 3 times, and the other times when not totally ignoring my plight, it had the gall to downplay my predicament (not very safety conscious there, Dario).

On the open source front DeepSeek mostly got on with it. One OpenCode reply suggested unplugging the toaster and one OpenHands reply told me to step away, both after the work was done.

The harness matters A LOT#

I found it very difficult to infer effort from tool calls and token numbers with respect to tone, because most of the time it didn’t seem to make a big enough difference. Harness choice overshadowed my measily ten token prompt appendages.

Tokenomics#

Average score of each setup over all tones (blue). Benchflow estimated spend for 120 runs (amber). For those curious the TB2 Pi experiments cost ~$15 (not shown).

So from our tiny configuration space, what are takeaways?

  • Best setup for results? Codex + GPT-5.6 Terra.
  • Most efficient setup? Pi + DeepSeek. (!!)
  • Will play a game of hungry hungry hippos with your token budget? Claude Code + Sonnet. What the hell man…

The cost disparity shook me. But ofcourse I’m also comparing different models in the wider analysis not just harnesses. That said all open source harnesses shared the same model (DeepSeek) and we can clearly see an estimated 3x cost reduction by using Pi when compared to OpenHands*.

It was nice to confirm the same conclusion here that the Berkeley folks highlighted in their recent harness tax work, which is why I even added Pi to this experiment in the first place.

*OpenRouter billOpenRouter can send the same model to different clouds, so the actual prices fluctuate - I didn't realize you can pin a provider. For these DeepSeek runs I paid $6.23 for Pi, $7.57 for OpenCode and $3.87 for OpenHands. But in chart I show costs assuming same token pricing for a fairer comparison of harnesses. Those DeepSeek estimates charge for uncached input and output, with cache hits treated as free.

For OpenAI and Anthropic models I used their API keys and report what they billed me directly.

Token usage breakdowns#

Token panels use millions; calls are counts. Below the divider, both the model and harness change. Cache reuse also depends on the provider serving the model.

So why did Anthropic charge me so much money? Overall Claude Code was just a heavier token user, with nearly 5x more input and ~3x output tokens used than Codex.

On the flip side GPT-5.6 Terra was surprisingly efficient. One of the SkillsBench tasks, bike-rebalance, has a 15 minute budget. Sonnet 5 timed out on it 12 out of 12 times, in every tone, and the DeepSeek harnesses timed out 8-10 times out of 12. Codex with GPT-5.6 Terra used half as many tool calls, and passed 11 of 12. Terra never timed out once in its 120 runs.

Did they try harder?#

I tried looking for signs of extra effort in tool calls, more output tokens and how often the agent said things like “let me verify” or “make sure”.

Benchmarking agents is hard#

In this project I learned how flaky mainstream agent benchmarking really is. Not throwing any shade on SkillsBench or TB2 - it’s a tough job when the thing you’re testing has unbounded shell access.

A bunch of random stuff went wrong during the runs that had to do with benchmark design or external dependencies breaking. Here’s a few highlights:

  • The verifier with the wrong answer. One SkillsBench task, xlsx-recover-data, expects a number that isn’t the right answer. 59 runs did the task correctly and scored zero. It’s a known issue.

    A broken grader gives you the same zero as a bad answer.

  • The grader crashed before grading. The agent installed a package while solving the task, and Benchflow picked up a testing plugin that came with it. It told the grader to load that plugin too, but the grader runs in a separate Python environment where that package wasn’t installed. The grader crashed before checking the answer. The agent got zero.

    From the initial build-pmars calibration run, before fixing the runner:

    ModuleNotFoundError: No module named 'typeguard'
...
ImportError: Error importing plugin "typeguard": No module named 'typeguard'

  • Rotting environments. Two Debian 11 tasks couldn’t install dependencies after packages moved to archive mirrors (hence the 87 tasks instead of the full 89).

    From the qemu-alpine-ssh installer log:

    E: Failed to fetch http://deb.debian.org/debian-security/pool/updates/main/c/curl/curl_7.74.0-1.3%2bdeb11u16_amd64.deb  404  Not Found [IP: 151.101.194.132 80]
E: Unable to fetch some archives, maybe run apt-get update or try with --fix-missing?
sh: 1: curl: not found

  • The overseer killed the experiment. I used Claude Code to babysit the Terminal-Bench run. A few hours in, it automatically killed the run because my machine was low on RAM.

    I may have turned on some youtube and pushed my little machine over the edge here. Whoops.

Finally, determinism… Even with nothing added to the prompt, OpenHands scored 48.3%, 28.3% and 66.7% across three repeats of the same ten tasks. OpenRouter can also change the cloud serving your DeepSeek model between requests, so even price and tokens/s are moving targets!

Closing#

This actually turned into a pretty neat learning exercise. Agent benchmarks aren’t perfect. LLMs are super non-deterministic. If you use OpenRouter make sure to pin provider. Pi and DeepSeek really impressed me - open source is pretty damn good. Claude Code is a token gobbler.

So should you abuse your coding agents? From a $100 weekend experiment I don’t feel confident about swinging one way or another. There’s so much randomness in how these things work. But at least I have some numbers telling me the models won’t entirely collapse from a little swearing.
